# Importing CUDA and Metal into qpel

`qpel.py import` reads ordinary CUDA (`.cu`) or Metal Shading Language (`.metal`) source and writes a qpel program (`program.qpel.json`). `qpel.py translate` also builds the CUDA and Metal package from it, so a CUDA kernel comes out as Metal and the other way round. Neither needs the MPS IDE, a CUDA SDK or a GPU.

```sh
python3 portable/qpel.py import portable/cuda_examples/threshold.cu --out /tmp/threshold.qpel.json
python3 portable/qpel.py translate portable/metal_examples/threshold.metal --out /tmp/threshold-pkg --block 32
python3 portable/qpel.py import kernels.cu --plan pipeline.json --out program.qpel.json
```

## How it works

clang parses the source and dumps its AST as JSON (`frontends/clang_ast.py`). CUDA is parsed host-only against the small stub headers in `frontends/include/` (the stubs only declare names; no code is generated from them). Metal is parsed by `xcrun metal`. Macros and includes are therefore expanded exactly as the real compilers would.

One mapper (`frontends/c_import.py`) turns that AST into qpel IR for both languages. The language differences sit in two small dialect tables: how a kernel is marked (`__global__` / `kernel`), where a buffer binding comes from (parameter position / `[[buffer(n)]]`), how the thread index is spelled, and the atomic calls. The finished program then goes through the normal qpel checks (types, scopes, pipeline effects, constant bounds), which make the final decision.

Anything without a qpel equivalent is rejected with its location and a reason code, for example:

```
kernels.cu:14:9: [for-loop] for statements are not in qpel yet
kernels.cu:21:30: [do-loop] do statements are not in qpel yet
```

## What is accepted

- Any number of kernels and device helper functions in one file; helpers must come before their callers.
- The thread index `blockIdx.a * blockDim.a + threadIdx.a` for each axis a = x, y, z (operands in any order, in a local or inline), or a Metal `[[thread_position_in_grid]]` parameter of type `uint`, `uint2` or `uint3`. A kernel that uses only the x index stays 1D; one that uses y or z, or a `uint2`/`uint3` position, becomes a 2D/3D kernel over its `uint3` shape. Without a launch plan its block is 16 × 16 × 1.
- Buffers of `unsigned char` (read-only), `unsigned int`, `int`, `float` and `half`/`__half`; a `uint3` shape, either by value or as `constant uint3&`.
- CUDA atomic buffers are plain `unsigned int*`. A buffer counts as atomic when an atomic call uses it, either directly or through a helper, or through another kernel that shares its resource. `atomicAdd(p, 0u)` becomes an atomic load. Metal atomics must use `memory_order_relaxed`.
- `if`/`else`, `while`, `for`, `break`, `continue`, `return`, locals with an initializer, `=`, the compound assignments (computed in C's type and converted back, as C does) and `++`/`--` on 32-bit integers.
- `unsigned int` and `int` arithmetic, comparison, logical, bitwise, shift and `~` operators; `?:`; `min`/`max`; `fmaf`/`__fmaf_rn`/`fma`; float/half conversions; int/unsigned conversions, both implicit and explicit. Signed arithmetic gets qpel's defined wrapping (NUMERICS.md).
- C promotes `unsigned char` to `int`. When such a value provably can't go negative (a comparison of two bytes, `&`/`|`/`^` of bytes), it stays unsigned, so byte kernels don't turn into signed code.
- Programs that need `else`, `for`, `int`, shifts or `~` are written as IR version 2; all others stay version 1.
- Template functions used with several sets of arguments: each instantiation becomes its own function, named by Metal's `[[host_name("...")]]` or by its arguments (`unary_op_kernel<op_abs, __half>` → `unary_op_kernel_op_abs_f16`); the report keeps the original spelling for calling it. Non-type template parameters read as the value they were replaced by, and a function passed as a template argument is called directly.
- Device functions defined in the library's own headers (llama.cpp's `common.cuh`) are imported when the file's GPU code reaches them; system headers never are. The report lists them as an adaptation.
- Raw thread builtins: a kernel that reads CUDA's `threadIdx`, `blockIdx`, `blockDim` or `gridDim` outside the global index, or takes Metal's threadgroup position, thread position in the group, group size or group count, becomes a `Groups` kernel (NUMERICS.md, launch geometry). Its size arguments stay arguments, and inside it the global index is read literally (group × size + local), so CUDA and Metal spellings import to the same program. Without a plan, buffers are sized by a shape `size` and the kernel runs one thread per element of it in groups of 64.
- CUDA's `__fadd_rn`/`__fsub_rn`/`__fmul_rn`/`__fdiv_rn` are qpel's ordinary float operators (f32-strict-v1).
- C names that qpel or a backend reserves (`min`, `max`, `half`, `kernel`, ...) get a trailing `_`, listed as an adaptation.
- Struct arguments of scalar fields (ggml's `constant ggml_metal_kargs_* & args`, or a struct by value in CUDA) and their fields; pointer locals into device buffers, pointer casts between element types (`View`), and pointer arithmetic; Metal function constants, given with `import_source(..., constants={...})`, with the branches they decide folded; program-scope scalar constants (`constant float SQRT_2_OVER_PI = ...`), read as their value; overloaded functions, each its own function; Metal's `clamp` and `select`; attributed statements (`[[unroll]]`). Program-scope arrays (lookup tables) are an error only where used.
- `import_source(..., kernels=[...])` (and the corpus programs) imports only the named kernels and the functions they reach, so each instantiation of a library operation is its own program.
- Math functions on `float`: `fabsf`/`fabs`/Metal `abs`, `fminf`, `fmaxf`, `floorf`, `ceilf`, `truncf`, `roundf`, `copysignf`, `sqrtf`/`__fsqrt_rn`, `expf`, `exp2f`, `logf`, `log2f`, `sinf`, `cosf`, `tanhf`, and the same names without `f` (NUMERICS.md, math functions). Conversions written as constructors (`__half(f)`), `bool` to numbers, `__half` scalar arguments, and element counts of any integer type (`int k`).
- IR version 3 (NUMERICS.md): `signed char`/`char`, `unsigned short`/`short`, `long long`/`int64_t`/`long`, `unsigned long long`/`uint64_t`/`size_t` (Metal `ushort`, `long`, `ulong`), `__nv_bfloat16`/`bfloat`, as locals, arguments and buffers of any of them, writable `unsigned char` buffers, and float-to-integer conversions (which qpel saturates). C's conversions between integer types become explicit `Cast` nodes, except widenings that keep signedness, which change nothing qpel computes. A chain of casts is converted one step at a time, so `(long long)(unsigned char)x` keeps the truncation to 8 bits. Integer constant expressions of the new types (`-5ll`, `(short)(-32767 - 1)`) become one `Constant`. Re-importing generated code reads back qpel's own spellings at every width: wrapping `(long long)((unsigned long long)a op (unsigned long long)b)`, `qpel_i64_div`/`qpel_i64_rem`, shift counts masked with 63, `qpel_f32_to_*`.

- Scalar kernel arguments of type `unsigned int`, `int` and `float` (in Metal, `constant T&` parameters) stay ordinary arguments; the hosts take them as `values=`.
- IR version 4: local arrays of scalars (`uint32_t point[3] = {...}`, Metal `uint v[3]`), indexed by any integer expression, including as assignment targets (`point[i] ^= t`). Elements an initializer list leaves out are zero; an array without an initializer starts at zero (an adaptation). An array used other than by indexing (passed to a function, decayed to a pointer) is rejected (`array-use`).
- Vectors (`int2`-`int4`, `uint2`, `uint4`, `float2`-`float4`; `uint3` stays a shape): locals, helper parameters (by value or `const&`) and results become `vec<T, N>`, built from lists, `make_float3(...)` or Metal `float3(...)`. Non-const reference parameters become `ref` parameters; a kernel argument cannot be one. A kernel's vector buffer (`int4* bboxes`) becomes a buffer of its scalars scaled by N: `bboxes[i]` is `vec(bboxes[4i], ..., bboxes[4i + 3])`, `bboxes[i].w` one element, and `bboxes[i] = v` one store per element. `*p` is `p[0]` (with a pointer cast, the bits of a float read as an integer). CUDA's `min`/`max` on floats are `fmin`/`fmax`, and on mixed signedness compare in the result type, as CUDA's overloads do. A corpus program may carry a launch plan (`plan`). Shared memory (`__shared__ T a[N]`, Metal `threadgroup T a[N]`, default-constructed or not) becomes `shared<T, N>` and makes the kernel a Groups kernel, as do `__syncthreads`, `__syncthreads_count`, `threadgroup_barrier` and cooperative groups' `this_thread_block()` (`group_index()`, `thread_index()`, `thread_rank()`, `sync()`, `size()`). A comma in a for step gives several steps. A helper named like a Metal vector function (`normalize`, `dot`, ...) is renamed with a trailing _. A vector is read from a kernel buffer of its element type (`reinterpret_cast<const int4*>(coords)[i]` reads `coords[4*i]` to `coords[4*i + 3]`, and the plan sizes `coords` as `in M * 4`), built with `make_int4(...)` or a full list, or starts at zero. Other vector uses are rejected (`vector-init`).
- gsplat's code (2026-11-17, `frontends/records.py` and `c_import.py`): glm's vectors (`using vec3 = glm::vec<3, float>`; also `int` and `unsigned int` elements) are qpel vectors, with their components read through glm's anonymous unions (`x y z w`, also `r g b a` and `s t p q`) and built by glm's constructors of N scalars. A plain struct of scalar fields (no bases, no methods with bodies) is taken apart into its fields: a function returning one (`GaussianWeight eval_gaussian_weight(...)`) returns void and gives the fields through reference parameters `result_<field>`, a local of it (`GaussianWeight gw = eval(...)`) is one local per field, `gw.valid` reads `gw_valid`. A 2D local array `float pix_out[P][C]` is one array of P * C elements, read at `[p * C + c]` (when only its elements are used). A pointer parameter moved by `p += n` (`isect_offsets += image_id * tiles`, also under `if (masks != nullptr)`) is the parameter and a 64-bit offset local, `p[i]` read as `p[p_offset + i]`; comparisons with nullptr still test the argument, so an optional buffer stays optional. A block of dynamic shared memory of `int` or `float` may be carved too, and a view may start inside another (`reinterpret_cast<vec3 *>(&id_batch[BATCH_SIZE])`): the earlier one then holds that many elements, and only the last needs its length given. `__builtin_ctz`, `__builtin_clz` and `__builtin_popcount` of constants are folded. CUDA's `__expf` is qpel's `fast_exp` (IR version 20, within 3 + floor(2|x|) ulp; on NVIDIA the same `__expf`, on Metal `fast::exp`). The fast intrinsics `__logf`, `__sinf` and `__cosf` are read as qpel's bounded `log`, `sin` and `cos`, with an adaptation: at least as accurate as the original, not the same bits on NVIDIA.
- Metal's simdgroup matrices (IR version 13): `simdgroup_float8x8` and `simdgroup_half8x8` locals become `matrix<f32, 8, 8>` and `matrix<f16, 8, 8>` (a default-constructed one starts at zero; Metal leaves it undefined), `make_filled_simdgroup_matrix<T, 8, 8>(x)` is `qpel.matrix_fill`, `simdgroup_load(m, p + offset, stride)` and `simdgroup_store(m, p + offset, stride)` (also `&tile[offset]`) are `qpel.matrix_load` and `qpel.matrix_store`, and `simdgroup_multiply_accumulate(d, a, b, c)` and `simdgroup_multiply(d, a, b)` are `d = qpel.matrix_mma(a, b, c)` (c zero). Rejected (`matrix`): a matrix origin other than zero, `simdgroup_matrix(x)` (a diagonal matrix), and half accumulators. Arrays of matrices (IR version 14): `simdgroup_float8x8 mc[8];` is an `array<matrix<f32, 8, 8>, 8>` (elements an initializer leaves out start at zero), `simdgroup_load(m, p, stride, 0, false)` (the default origin, not transposed) is read as the three-argument load and `simdgroup_load(m, p, stride, 0, true)` (transposed) as `qpel.matrix_load_columns` (IR version 15; the same for `simdgroup_store`), and `simdgroup_barrier(mem_flags::mem_none)`, which orders no memory, is left out (an adaptation). `thread_index_in_threadgroup` is the thread's place in its group, `local.x + size.x (local.y + size.y local.z)`. NVIDIA's WMMA (`mma.h`, IR version 14): a `wmma::fragment` of shape 16 x 16 x 16 is an `array<matrix<T, 8, 8>, 4>` of its 2 x 2 blocks (block (i, j) at element 2 i + j), starting at zero; `fill_fragment` fills the four blocks, `load_matrix_sync(f, p, ld)` and `store_matrix_sync(p, f, ld, mem_row_major)` load and store them (block (i, j) at `p + 8 i ld + 8 j`; for a `col_major` fragment or `mem_col_major` layout at `p + 8 j ld + 8 i`, by `qpel.matrix_load_columns` and `matrix_store_columns`, IR version 15), and `mma_sync(d, a, b, c)` is `d[2i+j] = matrix_mma(a[2i+1], b[2+j], matrix_mma(a[2i], b[j], c[2i+j]))`, the 16 products of each element in k order (NVIDIA's tensor cores add them in their own; NUMERICS.md, Matrices). Inputs are half and accumulators float. Rejected (`matrix`): other shapes (32 x 8 x 16, 8 x 32 x 16), a memory layout that is not a constant, half accumulators, tf32, bf16 and integer inputs, saturation, and fragments that are parameters or read element by element (`x[i]`, whose place in the warp NVIDIA leaves unspecified). The differential stand-in `mma.h` runs WMMA originals on the CPU simulator, each thread holding the whole tile.
- Compile-time enum locals (2026-11-18): `static constexpr auto LOAD_ALGO = THREADS >= 32 ? BLOCK_LOAD_WARP_TRANSPOSE : BLOCK_LOAD_DIRECT;` (bitsandbytes' `kQuantizeBlockwise`) names a template argument, which clang has already resolved; the importer leaves it out. A kernel's `unsigned char*` buffer is read-only unless written: through `p[i] = ...`, or an address into it (`&p[i]`, `p + i`) passed to a call that takes a pointer to non-const (CUB's `BlockStore`).
- llama.cpp's Metal spellings (2026-11-18): `sign(x)` as Apple GPUs return it, 1 for x > 0, -1 for x < 0 and +0 otherwise (for +-0, NaN and the subnormals they flush; Metal's specification gives -0 for -0, which its default fast math does not keep); a kernel buffer declared `device const` but written through a cast (`(device T *) ((device char *) dst + o)`, kernel_tri) becomes writable, an adaptation; and a bool converted to half or bfloat16 is 1 or 0. Tested by tests/test_metal_builtins.py against the original on the Apple GPU.
- Small spellings (2026-11-18): `assert(e)` is left out, an adaptation (qpel kernels cannot stop the device; a kernel whose assertions hold runs the same; the condition must have no effects), `__builtin_expect(x, v)` is `x`, a stray `;` at file scope is nothing, and `sizeof` knows CUDA's vector types (`int4` 16, `float2` 8, `half2` 4, ...). tests/test_import_spellings.py.
- Subgroup barriers (IR version 16): CUDA's `__syncwarp()` (the full mask, given or by default) and Metal's `simdgroup_barrier` with memory flags are `qpel.subgroup_barrier()`; `__syncwarp` of some lanes is rejected (`call`), and `simdgroup_barrier(mem_none)`, which orders no memory, is left out.
- `powf` and `pow` on floats are `math.pow` (IR version 17), so mmcv's focal-loss kernels import.
- Half and bfloat arithmetic (2026-11-18): `half * half` (Metal), `-h`, `h += x` and comparisons of halves are read as the f32 operation rounded once to the half type, `cast<f16>(cast<f32>(a) * cast<f32>(b))`. That is the correctly rounded half operation (f32 has at least 2 p + 2 bits of a p-bit type), so the IR keeps f16 and bf16 for storage and needs no arithmetic of its own; tests/test_half_arithmetic.py matches Metal's own half arithmetic bit for bit on the Apple GPU and numpy's IEEE half on the CPU simulator.
- Metal's matrix types (2026-11-18): `half4x4`, `float2x4` and the others (also `matrix<half, 4, 4>` in a template) are C * R scalars, column-major as Metal stores them. A pointer to one is a buffer of its scalars (`(device const float4x4 *)(a) + i` is `a + 16 i`), a local or a `thread T &` parameter an `array<T, C * R>`, `m[i][j]` element `i R + j`, and a matrix assigned, converted (`(half4x4)(*src)`) or stored through a pointer is assigned element by element. tests/test_metal_matrices.py runs llama.cpp's idioms against the original on the Apple GPU.
- glm (2026-11-23, `frontends/glm.py`): gsplat computes with glm, a header-only C++ library of vector, matrix and quaternion classes. qpel does not reimplement glm: it runs glm's own instantiated code from the clang AST while reading, each scalar glm computes being the importer's reading of that very C expression, so the arithmetic is glm's operation for operation, in glm's order (a 3 x 3 product is glm's `tmp0 = A0 * B0.x; tmp0 += A1 * B0.y; ...`). glm's control flow is decided while reading: an `operator[]`'s switch on its constant index, `if constexpr`, loops over columns (unrolled); glm's asserts are left out. Constructors are found from the construction's type and signature (clang's JSON names no constructor), constructor templates and members written outside their class from glm's file of that class (`type_mat3x3.inl`). The std function objects glm's vector arithmetic passes along (`std::multiplies<T>()`) are their operator. A computed scalar that is not a name or a literal becomes a local `glm_N` before the statement, so each is computed once. At the source's own level a glm vector stays a qpel vector (as before), a glm matrix is an `array<T, C * R>`, column-major: a local, a helper parameter taking the caller's array by reference, a helper result a reference parameter `result` the helper writes (and its callers a local `glm_mN` before the statement). A helper's pointer to a glm object (`mat3 *covar`, given `covars ? &covar : nullptr`) is the caller's object by reference and a u32 `covar_present`. `m[i][j]` of the source's matrix may have indices known only at run time (component `i R + j`), and so may `v[k]` of its vector (glm's switch: `k == 1 ? y : (k == 2 ? z : x)`). Assignments to the source's objects write back the components that changed, values that read the object itself into locals first. Not read: a glm branch or loop whose condition is known only at run time, a helper taking both optional buffers and pointers to glm objects, a matrix result where it is passed on whole (a matrix is no qpel value), double-precision glm. A pointer parameter moved by `p += n` and tested as a condition (`covars ? &covar : nullptr`) tests the buffer itself (records.pointer_offsets, which before added the offset to the test). tests/test_gsplat_covariance.py: gsplat's `quat_scale_to_covar_preci` forward and gradient kernels, unmodified, bit for bit with the original (real glm) on the CPU simulator and on the Apple GPU.
- gsplat's projections (2026-11-23): a kernel whose thread index is compared with a local that is a product of its integer arguments (`const int64_t count = static_cast<int64_t>(B) * C * gaussian_count; if (idx >= count) return;`) is launched over a shape parameter `elements` of that many elements, which the caller gives (an adaptation; the kernel still compares with its own count, and a call of the original passes its arguments as before). An enum argument (`const CameraModelType camera_model`, an unscoped enum of `gsplat::`) is its underlying integer, also where clang spells the type with its namespace; a call of the original passes `static_cast<gsplat::CameraModelType>(v)`. glm's `atan(y, x)` reaches `atan2f`, qpel's `math.atan2` (IR version 22). tests/test_gsplat_projection.py: `projection_ewa_3dgs_fused_fwd_kernel`, unmodified, for the pinhole, orthographic and fisheye cameras, covariances given or from quaternions and scales, with and without opacities: bit for bit with the original on the CPU simulator, and on the Apple GPU where no bounded function decides (the fisheye's atan2 and an opacity's log within their bounds, radii from ceil then within one).
- gsplat's spherical harmonics (2026-11-23): the K = 16, D = 3 forward kernel gsplat runs for RGB colours, one per coefficient type and degree. Its wide loads `reinterpret_cast<V *>(a)[k] = reinterpret_cast<const V *>(p)[i]` (a `uint4` or `ushort4` at once, V and the element type T both known) are the element copies they stand for, `a[k W + j] = p[i W + j]` for j < W = sizeof(V) / sizeof(T) (records.wide_copies). A helper whose pointer parameter is given a local array (`sh_coeffs_to_color_fast(..., sh_coeffs, out_color)`, the same helper given buffers by the generic kernel) gets a copy for those arrays, its parameters `const T (&p)[N]` (IR version 10), named with the lengths (`_a48_3`; records.array_arguments). `std::is_same_v<A, B>` in device code is its value (the instances clang keeps in its system headers, statics.constant_values). An alias template `template <class T> using a = typename C<T>::m` (ATen's `opmath_type`) is desugared from C's specializations (statics.alias_templates). A default argument is the parameter's default; a null given for a buffer a helper tests (`viewmat_rs = nullptr`) is an unset view `<name>_absent` and its presence `0u`, and `c ? nullptr : p + k` passes `p + (c ? 0 : k)`, so an absent buffer is never offset. A launch-sized shared array of a kernel not imported needs no length (the original's other kernels run it as one element). `rsqrtf` is `math.rsqrt` (IR version 23). tests/test_gsplat_spherical_harmonics.py: `spherical_harmonics_fwd_kernel_k16_3channel`, unmodified, float and half coefficients, degrees 0 to 3, unpacked and packed, with masks and camera offsets: bit for bit with the original on the CPU simulator; on the Apple GPU bit for bit at degree 0, and above it within the error rsqrt's bound allows a sum of terms (2 MATH_ULPS epsilons x (degree + 1) x sum |c_k| max |Y_k|).
- gsplat's generic spherical harmonics (2026-11-23): `spherical_harmonics_fwd_kernel` and `spherical_harmonics_l1_plus_fwd_kernel`, any K, D and degree. Their grids are sized by `(packed ? gaussian_count : B * C * gaussian_count) * D`: a conditional count is the hidden `elements` shape like a product of arguments (the caller gives the count that applies; the kernel still compares with its own). The L1-plus host passes K = coeffs.size(-2), the stored count without the degree-0 term. tests/test_gsplat_sh_generic.py: K up to 25, D up to 5, degrees 0 to 4, dense, packed and in chunks: bit for bit with the original on the CPU simulator; on the Apple GPU within the same rsqrt bound.
- gsplat's simple projection (2026-11-23): a thread index compared with a product written in the comparison itself (`if (idx >= B * C * N) return;`) is the same hidden `elements` shape as a product held in a local. tests/test_gsplat_projection_simple.py: `projection_ewa_simple_fwd_kernel` and its gradient `projection_ewa_simple_bwd_kernel`, unmodified, for the pinhole, orthographic and fisheye cameras: bit for bit with the original on the CPU simulator; on the Apple GPU bit for bit for pinhole and orthographic, the fisheye within 16 MATH_ULPS epsilon of the largest output of each gaussian (its atan2 and theta / r may cancel).
- gsplat's spherical-harmonics gradients (2026-11-24): `spherical_harmonics_bwd_kernel` and `spherical_harmonics_l1_plus_bwd_kernel`, one per degree. A local `std::array<T, N> acc{}` is the C array `T acc[N]` it wraps, zero-filled; `acc[k]` is an element and `acc.data()` the array given to a helper's pointer (records.std_arrays; other uses are reported). A helper copied for a local array that some constant index of the helper overruns (`acc[15]` of a 1-element array, under `if (degree < 1) return;`) is also copied for the integer constants the call passes (`degree` given `DEGREE`), and the branches those constants rule out are dropped (records.array_arguments, names `_a1_k0_...`). `cg::coalesced_threads()`, `cg::labeled_partition` and `cg::binary_partition` of it are the calling thread alone, which CUDA allows (since Volta a coalesced group may be any set of threads that includes the caller): `cg::reduce` and `cg::inclusive_scan` over one are the value, `thread_rank()` 0 and `size()` 1 (frontends/coalesced.py, an adaptation; the simulator's cooperative_groups.h does the same for originals). The sums one thread of each label added atomically are then added by every thread; only the order of float additions an atomic sum leaves open changes. `v->x = e` through a helper's `vec3 *v` writes the caller's vector (glm.py's pointers to glm objects). A pointer local into an atomic buffer (`float *v_mean = v_means + k`, then `gpuAtomicAdd(v_mean + 1, ...)`) makes that buffer atomic and is read as its initializer at each use, as an unaligned view is; it may not change. tests/test_gsplat_sh_backward.py: degrees 0 to 4 (L1-plus 1 to 4), dense, packed and a device's chunk, with and without v_means and v_viewdirs: bit for bit with the original on the CPU simulator (both run their threads one after another, `Program(sequential=True)`, so the atomic additions come in the same order); on the Apple GPU within 2 MATH_ULPS epsilons x (degree + 1) of the scale of each gradient. The L1-plus kernel of degree 0, which declares a `std::array` of no elements after it returns, is still reported (`local-type`).
- Labeled partitions of a warp (2026-11-24): `auto warp = cg::tiled_partition<32>(cg::this_thread_block()); auto g = cg::labeled_partition(warp, label);` (also a `thread_block_tile<32>` declared directly). When the group is used only to sum values (`v = cg::reduce(g, v, cg::plus<T>())`, directly or in a helper whose every statement is such a sum through a reference parameter or a call to another such helper) and in `if (g.thread_rank() == 0) { ... }` blocks (no `else`) that only move pointer parameters and add sums, differences of sums or the thread's own values atomically, it is read as the calling thread alone: each thread adds its own values, so each atomic total is the same sum with its float additions in another order (frontends/coalesced.py, an adaptation). A summed value read anywhere else, a product of sums, a constant added once per group, an `else`, or any operation but `plus` is reported. The simulator's cooperative_groups.h builds real `thread_block_tile`s and labeled partitions (lanes gathered across the warp) for originals, which run threaded. `atomicAdd_system` is an atomic add (gsplat's `add_counts_kernel`). tests/test_labeled_partition.py.
- Pointers to blocks of bytes (2026-11-19): a struct of scalars and arrays of scalars (llama.cpp's `block_q8_0`: a half scale `d`, then `int8_t qs[32]`) laid out as C lays it out on both platforms is read through its pointers as bytes, before the import. The pointer becomes `unsigned char *` (a `buffer<u8>`), `p + i` moves `i * sizeof(block)` bytes, `p->d` is `*(half *)(p + 0)` (a View) and an array field `p->qs` the pointer `(int8_t *)(p + 2)`. Anonymous unions and structs inside one (`block_q4_1`: a union of `{half d, m}` and `half2 dm`) are flattened, the union's members at its start; a vector field takes its room but is not read through the block. Metal's `uchar2` and `ushort4` (IR version 18) import, a vector's constant subscript `sc[0]` its element `sc.x`, and an integer converted to half goes through f32 (exact for every integer a finite half can hold). A half literal (Metal's `16.h`) of a value half holds exactly is the f32 literal converted, which rounds nothing. tests/test_llama_mul_mm.py runs `kernel_mul_mm`'s q8_0 and q4_0 instances against the original on the Apple GPU, bit for bit, and tests/test_llama_mul_mm_blocks.py every block format qpel reads (q1_0, q2_0, q4_0, q4_1, q5_0, q5_1, q8_0, mxfp4, q2_K to q6_K): the original dequantises its own random blocks (B the identity) for the oracle. The `iq` formats (iq1_s to iq4_xs) pass too, through byte views and unions:
- Byte views (2026-11-20): a pointer to `uint8_t` or `uint16_t` into a wider unsigned local, `(thread const uint8_t *)&aux32`, reads shifts of the local's current value (element k is `aux32 >> 8 k`, both platforms being little-endian); one into a program-scope table, `(constant uint8_t *)(iq2xxs_grid + i)`, is a `u32` local holding the element index i, element k is a shift of table element `i + k / 8`, and `grid = (constant uint8_t *)(iq2xxs_grid + j)` sets the index again. Neither is written through, and a table view is set again only to its own table. A const table passed to a function (llama.cpp's quantisers pass `kvalues_iq4nl_f` on) stays a module constant.
- Unaligned pointer locals (2026-11-20): an unaligned view is not held in a local (IR version 18), so a pointer local made of one (`device const uint32_t * q4 = (device const uint32_t *)xb->qs + 4*ib32` in iq4_xs, whose blocks are only 2-aligned) is its initializer, read again at each use; neither the local nor anything it is made of may be assigned.
- Vector view locals (2026-11-21): a pointer to a vector cast from a pointer local of its scalars, into a buffer or shared memory (`device float4 * D4 = (device float4 *) D`, `threadgroup float4 * C4 = (threadgroup float4 *) C` in llama.cpp's `kernel_mul_mm_id`), is a local of the scalar pointer's kind; `*(D4 + i)`, `D4[i]` and `*D4` read and write elements N i to N i + N - 1 one by one. The original's vector accesses assume the vector's alignment, so the element accesses read and write the same values. The view is not assigned again.
- Unions (2026-11-20): a local union of scalars of one width, 16 or 32 bits (iq1m_scale_t: `half f16` and `uint16_t u16`), is one unsigned word; a member is written as the word's bits and read from them, a float member through a bitcast (f16 and u16: IR version 19). tests/test_byte_views.py.
- Threadgroup char memory read as several types or from byte offsets (2026-11-18; llama.cpp's kernel_mul_mm: `sa = (threadgroup half *) shmem`, `sb = (threadgroup half *)(shmem + 4096)`, a float view for its output tile): shared memory of each type over the whole block, a cast its type's array from the byte offset over the type's size. A type's array holds what was written as that type, so a program must read bytes back only as the type it wrote them as (kernel_mul_mm writes and reads each view's own data, after barriers).
- `is_same<A, B>::value` (Metal's library is a precompiled module, so its traits are not in the AST): read from the source text, A and B this template instance's arguments, compared as qpel types; and the values of static constexpr `integral_constant` members kept from system headers where they appear.
- Threadgroup memory sized by the host: a Metal kernel parameter `threadgroup T* p [[threadgroup(n)]]`, whose length the original's host sets at the launch, becomes `shared<T, N>` declared at the kernel's top, for the N given as `import_source(..., shared={'p': N})` (a corpus program's `"shared"`); without one the import reports `dynamic-shared`. It makes the kernel a Groups kernel. The behaviour rows run the unmodified original with the parameter rewritten as a kernel-scope `threadgroup T p[N]` (`differential/metal_text.py`, `sized_threadgroups`), the same memory with the same length. Metal thread builtins may be read by subscript: `tgpig[1]` is `tgpig.y`. Untyped threadgroup memory (`threadgroup char* shmem`) that every use casts to one type T (`(threadgroup uint16_t *) shmem + k`) becomes `shared<T, bytes / sizeof(T)>`, and those casts disappear; memory read as several types is refused (`shared`). The survey reports how many kernels need only such a length.
- CUDA dynamic shared memory, `extern __shared__ float smem[];`, whose length is the launch's third `<<<>>>` argument, becomes `shared<T, N>` for `shared={'smem': N}` (elements), as Metal threadgroup parameters do; the simulator and the NVIDIA hosts run the original with it declared `__shared__ float smem[N];` (`differential/simulate.py`, `sized_shared`).
- Library idioms (llama.cpp's cumsum): a device helper that reads `threadIdx`, `blockIdx`, `blockDim` or `gridDim` (itself or through its calls) takes each component it reads as a u32 parameter (`thread_idx_x`, `block_idx_x`, `block_dim_x`, `grid_dim_x`), which callers pass (a kernel its builtin, which makes it a Groups kernel); a call, without arguments, to a constexpr function that only returns an integer constant is that constant (`ggml_cuda_get_physical_warp_size()` is 32); `if constexpr` in a template instance is the branch clang chose; `(void)` statements without effects (`GGML_UNUSED_VARS`) and empty `do { } while (0)` are dropped; `*p = v` stores through a buffer or shared view pointer. For the subgroup check, `const int tid = threadIdx.x` (a local never assigned again) is the thread's x index, and a local holding a constant is that constant, so `tid / warp_size` names one subgroup.
- Pointers into shared memory (IR version 5): a Metal `threadgroup T* p = shmem + k` local, or a CUDA `T* p` whose value starts from a shared array or view, becomes a `shared<T>` view; Metal helper parameters `threadgroup T* s` become `shared<T>` parameters. A view of another element type than its memory is refused (`shared`); CUDA helper parameters stay buffers (CUDA pointers carry no address space), except qpel's own `qpel_shared_view<T>`.
- Compare-and-swap: CUDA's `atomicCAS` on `unsigned int*` and `int*` (the buffer becomes atomic), returning the value found; `atomicCAS` on 64-bit values is rejected as not portable (Metal has none). `std::numeric_limits<T>::max()`, `min()` and `lowest()` of an integer type become constants. `import_source(..., resources={'table': 'inout'})` gives a resource of the plan made without one another kind, for a buffer the caller fills and the kernels update in place.
- PyTorch extensions: `frontends/include/` has declaration-only stand-ins for the CUDA runtime and driver API and `cooperative_groups.h`, and `frontends/include/libraries/` for `torch/extension.h`, ATen, c10, pybind11 and cuBLAS (kept apart, so the CPU simulator and a real CUDA compiler can use them next to their own CUDA headers), so an extension's `.cu` files parse offline; its host functions are skipped as usual. `cooperative_groups::this_grid().thread_rank()` is the x thread index of a 1D kernel (refused in 2D/3D and Groups kernels). Namespace aliases and `using` declarations are skipped. Kernels defined out of line in a namespace (`__global__ void CUDA::k(...)`) keep their qualified name in the report, for calling the original.
- CUDA host functions (neither `__global__` nor `__device__`) are skipped and listed as host code; kernel launches in them parse but are not imported. Namespaces are flattened (function names must still be unique), which is listed as an adaptation.
- A function template used with one set of types is imported as that one function. `do ... while`, atomics on `int` (`atomicAdd`/`atomicMin`/`atomicExch` on `int*`, Metal `atomic_int`), conversions to `unsigned char` (low 8 bits), and locals declared without a value.
- 2D/3D kernels sized by scalar arguments: when each thread-index axis (or a local computed from one axis, such as `row = (blockIdx.y * blockDim.y + threadIdx.y) * 2`) is compared with exactly one `unsigned int` or `int` argument, those arguments become one shape `(W, H, 1)` and their uses read its members. Like the 1D count, this changes the host interface.
- Buffers of different sizes (PyTorch extensions): a 1D kernel's integer argument that the original's launch passes as `t.size(0)` or `t.numel()`, next to `t.data_ptr<T>()` for one of its buffers, is that buffer's length. It becomes a second shape `(N, 1, 1)` that sizes the buffer, and its uses read the shape's volume, as the 1D count does. A buffer the launch does not size takes the size of the buffers it is indexed with by the same local, through helper calls (TRELLIS.2's `hashmap_values[slot]` next to `hashmap_keys[slot]`); a buffer indexed by the thread index or by nothing it shares is sized by the grid. A buffer indexed together with buffers of two sizes is refused; pass a launch plan. Every size is checked by running: the CPU simulator puts an inaccessible page right after each buffer, so an access past the end stops the run.

Atomics (IR version 6): CUDA `atomicMax`, `atomicAnd`, `atomicOr`, `atomicXor`, `atomicSub` (an add of the negated value) and `atomicExch` whose result is used (an exchange); `atomicAdd` on `float*`, and `atomicAdd`/`atomicMin`/`atomicMax` on `unsigned long long*` as statements. Metal `atomic_fetch_max|and|or|xor|sub_explicit`, `atomic_exchange_explicit`, `atomic_float`, and `atomic_ulong` with `atomic_min|max_explicit`. Metal compare-exchange loops (`atomic_compare_exchange_weak_explicit` on `atomic_uint`/`atomic_int`, expected value a local) become qpel compare-and-swap before the statement, re-run each iteration of a loop they control (NUMERICS.md, Atomics); not after `&&`/`||`, in `?:`, in a `for` condition, or in a `do` loop with `continue`. Bitcasts: CUDA `__float_as_uint`, `__float_as_int`, `__uint_as_float`, `__int_as_float`, Metal `as_type<T>` between float and 32-bit integers.

CUB (LIBRARIES.md): `cub::BlockScan` and `cub::BlockReduce` calls, one item per thread, through qpel's own `<cub/cub.cuh>` (`include/qpel_cub`): each method call is inlined before import as the call of a library function that combines values in CUB's order, and its `TempStorage` becomes shared memory. A `__shared__` scalar (`__shared__ float carry;`) is one value for the group, `shared<T, 1>` read and written at `[0]` (it was imported as a thread's local, which is wrong as soon as threads share it). `T()` is zero. Local `typedef`s are read where they are used. Corpus sources may set macros their real build sets (`"defines"` in corpus.json, passed to clang, the simulator and nvcc): llama.cpp's CUB code needs `GGML_CUDA_USE_CUB`, which ggml defines from `CUDART_VERSION`.

mmcv pilots (2026-11-15): double that is float (NUMERICS.md, "Double precision that is float"); `a = b = c;` and `a = x, b = y;` statements; `bool` kernel arguments (a u32 argument, read as `!= 0`) and `bool*` buffers (u8 buffers of 0 and 1, one byte per element on both platforms); `sizeof` of a scalar type; scalar constants defined in a library header (`int const threadsPerBlock = sizeof(unsigned long long) * 8;`); and a CUDA helper's `T*` parameter that its calls pass shared memory becomes `shared<T>` (a parameter passed shared and device memory at different calls is rejected). mmcv's `roi_align_forward_cuda_kernel` and `nms_cuda` are corpus programs with hand-written plans (feature map, RoIs and outputs of three sizes; the mask's own size) and case generators with valid RoIs and clustered boxes (differential/cases.py); both pass the CPU simulator, the Apple GPU and GPGPU-Sim against the unmodified kernels.

pytorch_sparse pilot (2026-11-15, `frontends/statics.py`): static methods of a library's structs (`Reducer<scalar_t, REDUCE>::update(...)`) are ordinary functions, one per instantiated class (`Reducer_f32_0_update`); enumerators are their values and enum-typed expressions their underlying integer; a helper's `T *p` parameter that every call passes the address of a local (`update(&result, ...)`) and that the body only uses as `*p` is a reference parameter (IR version 4); `__ldg(p)` is `*p`; `std::numeric_limits<float>::max()`, `lowest()` and `min()` are FLT_MAX, -FLT_MAX and FLT_MIN; a `bool` template argument is spelled `true`/`false` when the original is called. The subgroup check reads CUDA's `blockDim.x * blockIdx.x + threadIdx.x` shifted by 5 (or divided by 32) as one value per warp, as it already read the grid index. pytorch_sparse's `spmm_kernel` (sum with values, mean, max with `arg_out`) and `spmm_value_bw_kernel` (mean) are corpus programs with plans and CSR case generators (empty rows, rows longer than a warp's 32 entries, K around the 32 columns of a block row); all four pass the CPU simulator, the Apple GPU and GPGPU-Sim against the unmodified kernels.

Optional buffers (2026-11-16, IR version 9; CORE.md): a kernel pointer parameter the body tests against null (`p != nullptr`, `p != NULL`, `p == nullptr`, `if (p)`) is an optional buffer, and the test is `qpel.present(p)`; its resource in the launch plan is optional, and a case may leave it out (`Case(..., omit=...)`, or by not giving an input), in which case the original also receives a null pointer. mmcv's `roi_pool_forward_cuda_kernel` (an optional `argmax`) is a corpus program: half its cases leave `argmax` out, and all pass the CPU simulator, the Apple GPU and GPGPU-Sim against the unmodified kernel. RoI pooling backward, deformable RoI pooling forward and backward, and a third `sync_bn` kernel import now as well.

Null tests beyond kernel parameters (2026-11-22, gsplat's tile intersection):
- A helper that tests a buffer parameter against null (`if (isect_ids != nullptr)` in gsplat's `accutile_process_tiles`) takes a `u32` parameter `<name>_present` after its own, and its tests read it; each call passes `qpel.present(p) ? 1u : 0u` for a kernel's optional buffer, its own flag for a helper's, and `1u` for any other buffer. A kernel parameter that it passes to such a helper is optional, as if the kernel tested it.
- An argument `c ? nullptr : p` (`first_pass ? nullptr : isect_ids`) passes the buffer `p`, and for a tested parameter the flag `c ? 0u : flag(p)`; a helper cannot use the null without undefined behaviour, so passing the buffer in its place changes nothing it may do. A null pointer passed on its own to a helper is not imported.
- A view local that may be null (`const bool *mask_img = nullptr; if (tile_mask != nullptr) mask_img = tile_mask + k;`) is a buffer local and a `u32` local `<name>_present`, set by every assignment (1 for a buffer, 0 for a null); its null tests read the flag. `bool *` views are `u8` views of 0 and 1, as `bool *` arguments are.
- `T{x}` of one scalar (`uint64_t{1}`) is `x` converted to `T`.

Rejected for now, each with its own code: atomics on anything but `unsigned int`, `int`, `float` and unsigned 64-bit (signed 64-bit atomics: Metal's are unsigned), `+=` or `++` on an element other threads update atomically, `switch`/`goto`, `double`, conversions involving `bool` and floats, thread builtins in device helpers, Metal's flat `thread_index_in_threadgroup` and simdgroup builtins, shared memory and barriers in user code, pointer locals, structs, vectors, and buffers of `double`, `void` or structs.

## Adaptations and warnings

`import-report.json` (in a translated package) and the `import` command's output list:

- **adaptations**: a kernel without a `uint3` shape is sized by the `unsigned int` that its thread index is compared with (`if (i >= n) return;`, `if (i < n) {...}`). That one argument becomes a qpel shape, and the generated hosts take `(n, 1, 1)` for it instead of the plain number. This is a host ABI change; all other scalar arguments keep their meaning.
- **adaptations** also list: plain reads and writes of a buffer that is updated atomically somewhere (CUDA allows this; qpel makes them relaxed atomic loads and stores), a non-const `unsigned char*` that is never written (read-only), a local without a value (starts at zero; reading it first is undefined in C), a second local with an existing name (renamed `name_2`), flattened namespaces, single-use templates, and an atomic accumulator that is updated before anything writes it (a `zeroed` resource, when there is no plan).
- **warnings**: kernels with a thread-index axis that is never compared against anything (directly, or through a local computed from it). CUDA rounds the grid up to whole blocks, so such a kernel also runs for indices past the end of its buffers.

## Launch plan

Source files do not say how kernels are launched. Without `--plan`, each kernel becomes one dispatch in source order with `--block` threads per group. Parameters with the same name share one resource, and the single shape parameter is the grid. With `--plan`, the given `pipeline.json` (the format qpel writes) is used instead. Buffers that a stage reads before any stage writes them must be inputs, so an accumulator needs an initialising kernel first, as in the `components` fixture.

## Real-source corpus and coverage

`corpus/` holds unmodified third-party GPU sources with their licences, listed in `corpus/corpus.json` with origin and SHA-256. The importer's declaration-only stand-ins (`frontends/include/`: CUDA, cooperative groups; `frontends/include/libraries/`: PyTorch, ATen, c10, pybind11, cuBLAS) only let clang parse them. `python3 -m frontends.corpus` reads each one in survey mode: the importer records every blocker instead of stopping at the first, keeps reading inside a rejected statement, and reports a parameter or local without a qpel type once rather than at every use. A kernel is importable when it and the device functions it calls have no blockers.

`corpus/coverage.json` records the blocker codes of every kernel (`--details` gives each blocker as `code at function:line`). `python3 -m frontends.corpus --check` (run by `check_all.py`) fails when it changes, and `tests/test_corpus.py` pins the SAM 2 part, so a new feature shows up as kernels becoming importable, and a regression cannot slip through; after checking the change, run `python3 -m frontends.corpus --update`. `--details` lists every blocker; `--messages` ranks blocker messages over the whole corpus. Sources are surveyed in parallel. In a survey, a template used with several types is reported once and its first instantiation is read too, so its other blockers show; kernels are read independently (parameters of different kernels are not linked by name).

clang's JSON AST is filtered while it streams in: declarations from system headers (libc++, the macOS SDK, the Metal toolchain) are dropped, keeping the file and line state clang's relative locations need. A llama.cpp file produces ~600 MB of AST JSON, nearly all of it libc++. Reading is bounded (2026-11-15): one top-level declaration with more than 1 GB of JSON is read past without being kept (`QPEL_AST_DECLARATION_MB`), and a source whose kept JSON passes 1 GB is refused (`QPEL_AST_UNIT_MB`); Python holds four to ten times the JSON it keeps (llama.cpp's Metal file: 555 MB kept, 2.2 GB; mamba's forward kernels: 5.6 GB). mamba's host launcher writes 100 GB of JSON for one function (nested `BOOL_SWITCH` lambdas, each instantiation written out in full) and its kernel template 0.5 GB for 161 instantiations; read whole, a survey of such sources in parallel took all of a 48 GB Mac's memory. A skipped declaration that is a kernel is recorded with the blocker `ast-too-large`, and so is a call of a skipped function (llama.cpp's `kernel_flash_attn_ext_impl`). Surveys run at most two sources at once (`QPEL_SURVEY_WORKERS`); the whole corpus peaks at about 17 GB.

**Extensions corpus (2026-11-15).** Four PyTorch extension libraries, unmodified at pinned commits with their licences and `SHA256SUMS`: mamba (`csrc/selective_scan`, Apache-2.0), pytorch_sparse (`csrc/cuda`, MIT), mmcv (`mmcv/ops/csrc`, CUDA kernels and their helpers, Apache-2.0) and gsplat (`gsplat/cuda`, with glm at its submodule commit, Apache-2.0 and MIT). 107 sources; the report gives coverage per repository, the headline number from here on. Entries may give the macros and language standard their real build has (`"defines"`, `"standard"`: gsplat is C++20 and, like mmcv, sees `__CUDACC__` as under nvcc). The stand-ins grew with them: ATen dispatch macros, `PackedTensorAccessor`, `c10::complex`, `optional` as `std::optional`, autograd and dispatcher declarations, cooperative-group tiles and reductions, libcu++ headers, CUDA's float math library and host overloads; any `<ATen/...>`, `<c10/...>` or `<torch/...>` header these sources include forwards to `torch/extension.h`. CUB calls outside qpel's subset (several items per thread, prefix callbacks, other functors, `BlockLoad`/`BlockStore`) are declared, so sources parse, and reported as `library`. A source clang still rejects is recorded as `(source does not parse)`, its kernels unknown. Kernels defined in a library's headers count when the source's host code launches them (`k<<<g, b>>>(...)`, as extensions do from their `.cu`), and, when that host code was too large to read, when they are instantiated in the source. Starting point, kernel instantiations as for llama.cpp: mmcv 65 of 473, gsplat 2 of 206, pytorch_sparse 2 of 22, mamba 0 of 480 (160 instantiations of one forward kernel per dtype file); 22 sources do not parse (mamba's backward kernels use CUB internals such as `BlockRakingLayout`; gsplat uses half-precision dispatch and a C++23 constant rule (now read: see below); mmcv's spconv its own tensor views). The largest blockers are general: calls of library device functions, struct and pointer locals, results and parameters of struct type, double arithmetic, and launch-sized shared memory.

**C++23 sources and LLVM's clang (2026-11-16).** gsplat's Lidar sources read a static member through a reference in a constant expression (`constexpr float kToAngle = 1.f / lidar.ANGLE_TO_PIXEL_SCALING_FACTOR`, `Lidars.cuh`), which C++23's P2280 allows and nvcc accepts. Xcode's clang (17) does not implement P2280; LLVM's clang does from version 20, in C++23 mode. So an entry whose `"standard"` is `c++23` is parsed with LLVM's clang (`clang_ast.llvm_clang()`: `QPEL_LLVM_CLANG`, or Homebrew's `llvm`); without one, such a source is reported as not parsing. The five gsplat sources that include `Lidars.cuh` are C++23 entries.

Second entry (2026-11-11): a slice of llama.cpp, commit 91d2fc3 (MIT): ten CUDA files and `ggml-metal.metal`, with the headers they include, unmodified under `corpus/llama.cpp/` and pinned by `SHA256SUMS` (checked by a unit test). Third entry (2026-11-12): Microsoft TRELLIS.2's `o-voxel` extension, commit 75fbf01 (MIT), the Phase 3 pilot: its serialisation (`z_order.cu`, `hilbert.cu`), hash-table (`hash.cu`) and voxel-rasterisation (`rasterize.cu`) kernels with their headers, under `corpus/trellis2/` and pinned by `SHA256SUMS`. First entry: SAM 2 `sam2/csrc/connected_components.cu` (commit 2b90b9f). On 2026-11-11 it started at 0 of 6 kernels importable. Threads past the original's grid fail the kernels' own guards, so the result is the same, but 4 times as many threads are launched. Launch geometry belongs to the host layer (Phase 7).

## Fuzzing

`python3 -m fuzz --count N --seed S` generates random well-typed programs (`fuzz/programs.py`: integer arithmetic at every width, shifts, division by values made odd, comparisons and selects, conversions in every direction, exact math) as qpel text and requires, for each: text that prints back identically; qpel → CUDA → qpel and qpel → Metal → qpel giving the same program; and identical outputs from the CUDA on the CPU simulator and the Metal on the Apple GPU. `fuzz/regressions/` keeps every program it once failed on; they run first. `check_all.py` runs 25 programs with seed 1.

## Behaviour rows

`python3 -m differential.matrix` runs every original (the example pairs, SAM 2 and its Metal port) and qpel's CUDA and Metal for it on the same cases, and requires identical outputs: CUDA on a CPU simulator, Metal on the Apple GPU. See `differential/README.md`.

## Round-trip matrix

`python3 -m frontends.roundtrip` (also part of `check_all.py` and the unit tests) checks:

| Row | Cases |
|---|---|
| qpel → CUDA → qpel | all 12 fixtures |
| qpel → Metal → qpel | all 12 fixtures |
| CUDA → qpel | `cuda_examples/*.cu` must import to their fixture |
| Metal → qpel | `metal_examples/*.metal` must import to the same fixture |

`box_sum` covers 2D/3D kernels: a 3×3 neighbourhood sum over a batch of images, with signed offsets and nested `for` loops, GPU-tested on sizes that are not multiples of the block. `scale_offset` covers scalar arguments: a `float` and an `int` argument next to the element count, GPU-tested with wrapping offsets and the hosts' argument checks. The fifth example, `signed_delta`, is the other version 2 case: signed arithmetic, an `if`/`else if`/`else` chain and a `for` loop with `continue` and `break`. Its fixture was made by importing the CUDA file, so its CUDA row only guards against regressions. The independent checks are the Metal file importing to the same program, both re-imports, nvcc and Metal compiling it, and the Apple GPU test against a NumPy model of C's semantics. Re-importing generated code also reads back qpel's own spellings: wrapping `(int)((unsigned)a + (unsigned)b)`, `qpel_i32_div`/`qpel_i32_rem` and masked shift counts.

Programs are compared as trees, so node ids, literal suffixes and float spelling don't count. CUDA → Metal and Metal → CUDA follow from these rows. A source that imports to a fixture's IR produces exactly that fixture's CUDA and Metal, and those are covered by the nvcc, Metal and Apple GPU checks.

## History

The first CUDA importer (September 2026) was a hand-written parser for one fixed kernel shape. It imported into a running MPS IDE over MCP. The clang importer replaces both, and imports the same four examples to the same programs.
